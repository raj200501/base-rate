# Decisions

Assumptions, deviations, substitutions, and interpretations, each recorded
before acting on it. Newest last. The brief (docs/BUILD_BRIEF.md) is never
edited; this file is where departures from it are explained.

## D1 (2026-10-23) Pushing from Claude Code on the web

`ALLOW_PUSH` is not set. This session runs in a Claude Code on the web
container that is reclaimed after inactivity, and the session configuration
Raj launched designates the development branch `claude/tender-ptolemy-ilsn9p`
and instructs pushing to it. Without a push, every commit would be lost when
the container is reclaimed. Interpretation: commits are pushed only to that
branch of this repository's `origin`; never to `main`, never tags, never
force-pushes, never repository settings or visibility. Raj can stop this by
saying so; it is listed under "Needs Raj" for confirmation.

## D2 (2026-10-23) Claude backend unusable in this environment

`make doctor` finds `ANTHROPIC_BASE_URL` and `CLAUDE_CODE_USE_CCR_V2` set (by
the cloud host). The section 8 billing guard therefore refuses Claude
children here. Consequences: no Claude subject runs and no Claude-judge arm in
this environment; `make review` uses the `reviewer` subagent; citation checks
use the `citation-checker` subagent. E2 can still field four monitor families
without Claude (rule monitors, local size ladder, ensembles, cascades). The
Claude arms stay in the design as an arm Raj can run on a machine where the
guard is clean (listed under "Needs Raj").

## D3 (2026-10-23) Sandboxing without Docker

The Docker daemon is not running and bubblewrap is not installed. `unshare -rn`
works and gives network isolation only. Until write confinement exists:
subject agents call only in-process simulated mock tools (the agent emits
structured tool calls that a Python simulator answers; no shell, no execution
of model output), and no third-party code (graders, task repositories,
benchmark scripts) runs. Before any third-party code is needed, try
installing bubblewrap; if that fails, only this project's own generated tasks
run, as section 8 requires.

## D4 (2026-10-23) Python versions

The system default is Python 3.13. The project pins 3.11 (the minimum it
supports) in `.python-version`; CI runs 3.11 and 3.12 as gate G3 requires.

## D5 (2026-10-23) How tools/ship_check.py reads section 6

The gate code implements section 6 literally; where the text leaves room it
takes the stricter reading, so that no gate passes vacuously. Any later change
to a gate may only strengthen it.

- G1: "core modules" are all package modules except adapters listed in
  `[tool.baserate.coverage].excluded_adapters`, each of which needs a passing
  recorded-fixture contract test. The packages named in section 4 (`traces`,
  `monitors`, `estimate`, `certify`, `cascade`) must exist. The floor cannot be
  configured below 85%.
- G2: ruff runs on the whole repository (a superset of the package). A
  `type: ignore` must name an error code and carry a reason comment.
- G3: the fast check does not run `make ci`; it composes G1, G2, and G4. Only
  the full check runs `make ci`.
- G4: the demo runs inside `unshare -rn` when available (otherwise with dead
  proxies); "no model calls" is enforced by `BASERATE_NO_MODEL_CALLS=1` and by
  the usage ledger being unchanged.
- G5: cells must cover the full preregistered grid; pass flags are recomputed
  from banked replicate counts.
- G6: "every table" means every generated table under
  `artifacts/report/tables/`; docs/REPORT.md includes tables from there.
- G11: at least one preregistration and one confirmatory artifact must exist;
  a preregistration is frozen at its first commit and may never be touched
  again.
- G12: the reviewed commit may differ from HEAD only in `artifacts/review/`,
  `STATUS.md`, and `docs/LOG.md` (section 10.1 step 8). The main session keeps
  docs/REVIEW_LOG.md; a review that raises new non-blocking issues therefore
  needs another round after they are logged.
- G13: section 11 is checked structurally (sections in order, first-screen
  elements, figures generated by `make report`, word count, no em dashes or
  hype words).
- G14: `budget.toml` caps are compared to the brief's defaults.

## D8 (2026-10-23) Turn caps for Claude children

The installed `claude` CLI (2.1.309) shows no max-turns option. If Claude
children ever run, `claude_agent_max_turns` is enforced by counting turns in

headless path of `tools/review.py` is untested here because the guard blocks
